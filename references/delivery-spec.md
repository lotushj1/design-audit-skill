# 交付規格與複驗

## 先辨識目前要交的品項

列出檔名、版本、平台或用途，並以使用者指定的核定資料確認適用範圍。確認前後稿的配對。若承接的是複驗，舊稿作為證據，交付判定以新版為準。若整批都要交，每一張才參與整組判定。

## 讀取原始匯出檔

從目前載入的 Skill 資料夾執行，圖片使用絕對路徑。沒有看到 QR 時，用 `--inspect-only` 量測原檔。看到 QR 時省略這個選項，即可同時讀取檔案資訊及解碼。

```sh
uv run --python 3.12 --with-requirements requirements.txt python scripts/decode_qr.py --inspect-only /路徑/交付圖.png
uv run --python 3.12 --with-requirements requirements.txt python scripts/decode_qr.py /路徑/有QR的交付圖.png
```

`facts` 回報實際檔案格式、依 EXIF 顯示方向的寬高、影格數，以及第一幀是否含非全不透明像素。輸出有透明像素時，再看透明的位置是否為設計所需。工具只視讀及解碼第一幀。若整個動畫或多幀是交付物，保留後續幀未驗證。只有截圖時，標示原始匯出規格待驗證，避免由縮圖或副檔名推測。

透明區在不同預覽底色上會有不同外觀。以「透明缺口」描述有檔案證據的問題，實色白邊需另外有像素或畫面證據。

## 比對與判級

| 欄位 | 核定值和來源 | 實測值和來源 | 結果 |
| --- | --- | --- | --- |
| 已核定的尺寸、格式、透明要求、活動資訊或 CTA | 保留精確值、版本與位置 | 檔案讀值、畫面引文或確認的最終落點 | 相符／不符／待驗證 |

只用對應該份交付物的核定要求。明確違反交付尺寸、格式或透明等硬規格至少列為 High，必修後再交。錯誤活動日期、主要 CTA 指向不相干內容等會影響使用的錯誤列為 Critical。拍攝、平台無障礙整體合規、實機掃描及印前工程需各自有證據，單次畫面或工具解碼不足以確認。

比對網址時，用已確認的最終文件、路徑及內容判定。若 QR 走網域別名但落在和畫面文字相同的文件，列為內容相符。若有一邊未讀回，就保留待驗證。相同網域指向不同文件、活動或年份，仍須依實際內容核對。

## 修正版回查

先逐一回查舊稿必修項，再獨立檢查新版有無新問題。以表格列「舊稿位置與證據｜新版證據｜已修正／仍存在／待驗證」。修正日期及網址時保留具體文字，不把舊稿問題搬到新版。交付判斷只涵蓋已讀取的檔案和已驗證的項目。
